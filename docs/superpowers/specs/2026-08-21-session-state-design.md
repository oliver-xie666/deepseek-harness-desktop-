# 会话与工作区真实状态设计

## 目标

让左侧工作区和会话列表由 `dsh-core::AppState` 的真实数据驱动。创建、选择、重命名、复制、删除会话以及切换工作区后，界面、内存状态和磁盘持久化保持一致。

## 范围

- 会话列表不再从 `Sidebar` 的硬编码数组初始化。
- 会话操作以会话 ID 为唯一键，不能再按标题匹配。
- 每个会话保存创建/更新时间；侧栏默认按最近活动时间排序，也支持按名称排序。
- 删除操作删除内存会话和对应的 `sessions/<id>.json`；若删除的是当前会话，激活下一个可用会话或清空激活态。
- 复制会话复制消息、diff、终端日志和工作区，但生成新的会话 ID 与标题。
- 工作区选择更新 `AppState.workspace_path`，重新扫描并显示当前工作区的文件树。
- 服务端产生 token、工具调用、diff、状态和终端日志后，更新会话更新时间并持久化。

不包含模型/权限/预设、对话卡片重绘、轨迹详情、设置页和 Explorer 面板布局；这些会在后续独立功能分支中处理。

## 架构

`AppState` 是唯一的会话事实来源。它提供会话生命周期方法和只读快照方法，并通过 `SessionPersistence` 对单个会话文件执行保存或删除。`Sidebar` 仅保存暂态 UI 状态（菜单、搜索、排序、正在重命名），并定期同步一个由 `AppState` 派生的会话快照。

工作区路径同样保存在 `AppState`。选择工作区后，核心状态更新路径；侧栏从该路径重新扫描 `FileNode`，并用该树作为后续 Explorer 接入的数据源。

## 数据流

```text
点击侧栏操作
  -> Sidebar 调用 AppState 生命周期方法
  -> AppState 修改 sessions / active_session_id / workspace_path
  -> SessionPersistence 保存或删除 sessions/<id>.json
  -> Sidebar 同步快照并重新渲染
```

服务端事件沿用同一条路径：更新对应 `Session` 后立即保存，避免重启丢失工具输出、终端日志或 Agent 状态。

## 错误处理

- 会话不存在时生命周期方法返回 `Ok(false)` 或 `None`，侧栏只重新同步，不创建伪会话。
- 删除磁盘文件失败时方法返回错误，并保留内存状态，避免 UI 显示“已删除”但重启后恢复。
- 工作区扫描失败时保留已选择路径、将 `file_tree` 置空；不会伪造目录内容。
- 加载旧会话文件时，新增时间字段采用 serde 默认值，保证已有会话可以读出。

## 验收

1. 新建、选择、改名、复制、删除会话后，内存快照和磁盘文件一致。
2. 按标题相同的两个会话仍可以被独立选择和删除。
3. 删除当前会话会可靠地切换激活态。
4. 服务端工具/终端事件写入后，重新加载会话仍可看到更新。
5. 切换工作区会更新 `workspace_path`，并使侧栏使用新目录的文件树。
